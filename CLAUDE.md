# metGameHUB

Трей-приложение (.NET 8 / WPF). Раз в 2 с смотрит процессы и включает системный HDR, пока запущена игра из библиотеки (Steam/Epic/GOG/Ubisoft/EA/Xbox/папки); выключает через 3 с после выхода, только если включило само. Также добавляет игры из папок и выбранные приложения в Steam как non-Steam ярлыки с обложками SteamGridDB.

## Структура
- `src/metGameHUB` (root namespace `MetGameHUB`): `Scan/` источники и `Library`, `Watch/` `ProcessWatcher`, `HdrController`, `DisplayConfigHdr`, `Update/` `Updater` (самообновление с GitHub Releases), `Steam/` текстовый и бинарный VDF, `ShortcutsFile`, `SteamGridDb`, `Artwork`, `SteamAdder`, `Advice/` советчик по графике (`Hardware`, `ConfigFinder`, `ClaudeClient`, `IniEditor`, `Advisor`, `UnrealScalability` — подписи `sg.*` для Unreal, `ChatAttachment` — вложения чата: картинки ≤1568 px, PDF, текстовые файлы), `Ui/` окно (страница игры `GamePage`: слева колонка иконок `GameStrip` для переключения игр — то же представление `rows`, что у сетки, переключение идёт через `ConfirmLeave`; иконка exe 96 px (`PrivateExtractIcons`) грузится в фоне для всех игр, у игр магазинов без `MainExe` exe подбирает `MainExe.Pick`; без иконки — кроп обложки, без обложки — буква; цель, таблица «Сейчас | Рекомендуется», «Применить»/«Отменить»; панель деталей показывает только «подобраны/не подобраны» и «Открыть»), трей, автозапуск, `Covers` (поиск обложек + кэш загрузок SteamGridDB), `Theme` (системная тема), `Backdrop` (DWM-акрил), `Themes/Dark.xaml`, `Light.xaml`, `AdviceTable` (строки таблицы из совета и снимка конфига), `ChatPanel` (поле чата на странице игры: вложения, Ctrl+V, перетаскивание, Win+H), `Controls.xaml` (стили контролов, все цвета через DynamicResource).
- `tests/metGameHUB.Tests` (xUnit), `tools/make-icon.ps1` (генерирует `src/metGameHUB/assets/icon.ico`; запускать с `-ExecutionPolicy Bypass`), спека и план в `docs/superpowers/`, отложенные темы в `docs/backlog.md`.
- Сторонних NuGet-пакетов кроме xUnit нет; комментарии в коде только там, где поведение неочевидно.

## Команды
- `dotnet build`, `dotnet test`
- `dotnet publish src/metGameHUB -c Release -o publish` — один exe, framework-dependent win-x64.
- Релиз: `git tag vX.Y.Z && git push origin vX.Y.Z` — `.github/workflows/release.yml` публикует два zip (framework-dependent и `-selfcontained`, версия из тега) и создаёт GitHub Release. CI (`ci.yml`) гоняет build и test на push/PR в master.
- `metGameHUB.exe --hdr status|on|off` — ручная проверка HDR; `--tray` — запуск без окна (так прописывается автозапуск в HKCU Run).

## Данные
`%AppData%\metGameHUB\`: `settings.json` (в том числе ключ API Claude, `ClaudeBaseUrl` — адрес сервера Claude, пусто = официальный API, `ClaudeModel` — общая модель, пусто = claude-opus-5-5, `ClaudeLocate`/`ClaudeRead`/`ClaudeAsk` — `{Model, Effort}` для поиска, разбора и подбора, пустое поле = общая модель / встроенный effort, `DefaultTarget` — цель по умолчанию), `library.json` (на игру в `Overrides`: `HdrEnabled`, `MainExe`, `SearchName`, `Target`, `ConfigPath` — абсолютный путь файла настроек, названный моделью (null = ещё не найден), последний `Advice` совета по графике и `Snapshot` — снимок текущих настроек конфига: список `CurrentSetting`, время разбора и время записи файла, и `Chat` — история уточнений совета парами user/assistant; очищается при новом подборе, смене пути конфига и «Вернуть исходный конфиг», кнопкой «Очистить»), `log.txt` (после 1 МБ ротация в `log.old`). Битый JSON переименовывается в `.bad`, применяются значения по умолчанию.
- `update\` — zip и распакованный релиз во время обновления; удаляется при следующем старте.
- `covers\` — обложки SteamGridDB для игр не из Steam; имя файла — безопасное имя папки игры плюс 8 hex-символов хэша пути; временные файлы пишутся как `~имя`, поэтому недокачанный файл никогда не подхватывается.

## Неочевидное
- HDR переключается через DisplayConfig `GET_ADVANCED_COLOR_INFO_2` (type 15) / `SET_HDR_STATE` (type 16), на старых Windows откат на type 9/10: на 24H2+ старый API путает HDR с автоуправлением цветом.
- При записи в Steam обложки и иконки сначала качаются при работающем Steam (appid берётся из черновой копии `shortcuts.vdf`, которая не сохраняется); затем приложение само закрывает Steam (`steam.exe -shutdown`), перечитывает файл, пишет его атомарно с копией `.bak` и запускает Steam обратно. Одна запись на игру по папке игры; appid существующих записей сохраняется; `icon` и `LaunchOptions` существующей записи перезаписываются только непустым значением.
- Переименование из metGameHDR (v0.3.0): при обращении к `AppPaths.Dir` папка `%AppData%metGameHDR` один раз переносится в `metGameHUB` (только если новой ещё нет); при старте трея старое значение `metGameHDR` в HKCU Run удаляется и записывается `metGameHUB` с текущим путём. Старые установки не самообновляются через переименование: их апдейтер ищет в zip `metGameHDR.exe`.
- Один экземпляр: мьютекс `Local\metGameHUB`; повторный запуск сигналит событием `Local\metGameHUB.Show`, первый экземпляр показывает окно, второй сразу выходит. `--hdr` идёт мимо мьютекса.
- Библиотека пересканируется при каждом старте в фоне (окно сразу показывает кэш), а также после изменения папок.
- Сам `metGameHUB.exe` (`Environment.ProcessPath`) при каждом скане добавляется к приложениям (`LibraryScanner.AppsWithSelf`), в `Settings.Apps` не сохраняется — чтобы хаб можно было добавить в Steam.
- В `Settings.Apps` хранится путь, выбранный пользователем, в том числе сам `.lnk`; ярлык разрешается при сканировании, его аргументы уходят в `LaunchOptions` записи Steam. Папки без exe в корне тоже считаются играми (`MainExe = null`).
- Пути папок игр нормализуются без завершающего `\` при сканировании — это общий ключ для дедупликации, настроек игр и поиска по процессу.
- Песочница Bash/PowerShell у Claude Code на этой машине подменяет `%AppData%` и блокирует смену настроек дисплея: реальные проверки HDR/Steam/автозапуска запускать через терминал пользователя (run_in_terminal), не из песочницы.
- Обложки Steam-игр берутся из собственного кэша клиента `appcache\librarycache\<appid>\library_600x900.jpg` (старая плоская раскладка тоже проверяется) — они есть только у игр, которые Steam успел закэшировать; для этого в `Game.SteamAppId` хранится appid из манифеста. Игры из папок/приложений, уже добавленные в Steam, берут `userdata\<user>\config\grid\<appid>p.*`. Загрузка из SteamGridDB — только при заданном ключе, не более 3 параллельно; до перезапуска запоминается только «нет совпадения», сетевые ошибки повторяются при следующем пересканировании.
- Тема читается из `HKCU\...\Themes\Personalize\AppsUseLightTheme` и меняется на лету через `SystemEvents.UserPreferenceChanged`; чтобы стили перекрашивались, они обязаны использовать `DynamicResource`.
- Стекло: `DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE=38, DWMSBT_TRANSIENTWINDOW=3)` + `DWMWA_USE_IMMERSIVE_DARK_MODE=20`; при ошибке (Windows 10) окно откатывается на сплошной фон темы.
- Неявный стиль `Window` не применяется к `MainWindow` (наследник), поэтому окно явно ставит `Style="{StaticResource {x:Type Window}}"`; неявный стиль `TextBlock` принудительно задаёт цвет текста внутри шаблонов, поэтому цвета бейджей/карточек задаются через Style. Бейджи карточек показывают только проблемные состояния (`nonHDR`, зачёркнутый `Steam`).
- Обновление: при старте проверяется `releases/latest` на GitHub (через 10 с, затем раз в 24 ч; вручную — кнопкой «Проверить обновления» в настройках рядом с версией, через `MainWindow.CheckUpdates`, который задаёт `App`); по кнопке zip качается в `%AppData%\metGameHUB\update\`, текущий exe переименовывается в `.old` (Windows это разрешает для запущенного файла), новый ставится на его место, мьютекс освобождается до `Process.Start`, иначе новый экземпляр выйдет как второй; `.old` и `update\` удаляются при следующем старте и повторно через 10 с: завершающийся старый процесс может ещё держать `.old`; если новый exe не запустился, `.old` возвращается на место и запускается старая версия. Self-contained определяется по пустому `typeof(object).Assembly.Location`.
- Советчик по графике (`Advice/`) делает три запроса: `Advisor.LocateAsync` («Найти конфиг») — модель по списку файлов папки игры и найденным кандидатам называет один файл настроек и формат (`ini`/`json`/`none`), приложение раскрывает `%LocalAppData%`/`%AppData%`/`%UserProfile%`/`%ProgramData%`/`<InstallDir>` и сохраняет путь в `ConfigPath` даже для ещё не созданного файла; затем `Advisor.ReadAsync` (разбор: без веб-поиска, effort low, 4000 токенов) — модель по тому же файлу возвращает текущие настройки словами (`Snapshot`), страница показывает их сразу, до подбора; для Unreal `UnrealScalability` разбирает `sg.*` локально (Low/Medium/High/Epic/Cinematic) и показывает как временные строки, пока модель отвечает; затем `AskAsync` («Подобрать») — модель получает этот единственный файл (до 32 КБ, секреты замаскированы) и сама разбирает текущие значения (`Current`), а для пунктов, лежащих в файле, возвращает `Section`/`Key`/`Value` для записи. Приложение только проверяет и пишет. Путь от модели допустим лишь внутри `%LocalAppData%`, `%AppData%`, профиля, `%ProgramData%`, Documents, Saved Games или папки игры (`Advisor.IsAllowedPath`, проверяется и при чтении сохранённого пути), иначе считается «none». `AskAsync` без найденного пути уходит без файла. Снимок свежий, пока время записи файла совпадает с `FileStamp` (`Advisor.IsSnapshotFresh`); устаревший снимок не подмешивается к таблице совета, на странице появляется «Конфиг изменился — Обновить»; снимок сбрасывается при смене пути конфига и обновляется при подборе, применении и восстановлении. Ответ с временем сохраняется в `library.json` на игру (цель игры при этом не меняется: «Подобрать» не закрепляет цель по умолчанию). Запросы не используют structured output (цитаты веб-поиска с ним дают 400): схема лежит в системном промпте, а JSON ответа собирается из text-блоков после последнего блока результата поиска (допускается ```-ограждение). Имя и exe для поиска конфигов и запроса берутся из переопределений игры. Игра должна быть закрыта для записи.
- Содержимое найденного конфига уходит в Anthropic API: только один файл, выбранный моделью на шаге поиска, до 32 К символов, значения строк, ключ которых содержит `password`, `passwd`, `pwd`, `token`, `secret`, `session`, `auth`, `ticket` или `credential`, заменяются на `***` (`ConfigFinder.MaskSecrets`). `ConfigFinder.Find` теперь только подсказывает модели пути-кандидаты в запросе поиска (порядок: Unreal по папке проекта в каталоге игры `<P>\Binaries` + `<P>\Content` → `%LocalAppData%\<P>\Saved\Config\*\GameUserSettings.ini`, Unreal по имени, `%LocalAppData%` и вложенные папки по нестрогому совпадению имени без Microsoft, Temp и т.п., My Games и Saved Games, корень игры; в каждой папке файлы с `prefs` в имени идут первыми; `steam_emu*` и `cream_api*` пропускаются). Веб-поиск у модели: до 2 обращений на поиск конфига, до 3 на подбор настроек.
- UI подбора сначала ищет конфиг (если он ещё не найден: `ConfigPath`/`ConfigNote` пусты), затем (для найденного существующего файла) разбирает его запросом чтения (`Advisor.ReadAsync`) и показывает «Сейчас», и только потом спрашивает совет; провал чтения не трогает таблицу; если файл найденного пути ещё не создан, второй запрос не отправляется. Уход со страницы игры во время запроса отменяет его после подтверждения.
- Запись конфига: при первом применении рядом создаётся `<файл>.orig` (больше не перезаписывается), при каждом применении — `<файл>.bak` с предыдущим содержимым; новое содержимое пишется через `.tmp` и `File.Move`. «Вернуть исходный конфиг» (`Advisor.Restore`, кнопка видна при наличии `.orig`) кладёт `.orig` на место тем же способом, текущий файл уходит в `.bak`, а `Current` сохранённого совета перечитывается из файла сырыми значениями.
- Скрытые игры (`GameOverride.Hidden`): фильтр `CollectionView` над `rows` убирает их из сетки, пока не включено «Показать скрытые»; `Library.FindByPath` их пропускает, поэтому HDR для них не включается.
- Тесты `tests/.../Advice` используют namespace `MetGameHUB.Tests`, а не `MetGameHUB.Tests.Advice`: иначе `Advice.*` внутри тестов резолвится в тестовый namespace.
- Цель игры — шаг ползунка `GoalStep` (null = по умолчанию из настроек); FPS шага считает `GoalTargets` от частоты монитора (1 Гц от EnumDisplaySettings = «по умолчанию железа», считается как 60), модель получает `goal {mode, fps}`; старые `Goal`/`DefaultFps`/`DefaultPriority` при загрузке отбрасываются.
- В запросах к Claude всегда явно задан `output_config.effort`: по умолчанию поиск конфига и подбор — `"medium"`, запрос чтения конфига — `"low"` и без `web_search`; так стоимость не менялась при смене модели. Модель и effort каждой задачи можно переопределить в настройках (`ClaudeChoice`: задача → `ClaudeModel` → claude-opus-5-5; effort задачи → встроенный); `web_search` ограничен 2 использованиями при поиске конфига и 3 при подборе.
- Редактор INI: комментарий `;`/`#` после пробела в конце строки `ключ=значение` сохраняется; одиночный ключ без значения получает `=`; при повторяющейся секции правится первое вхождение ключа, а недостающий ключ дописывается в первую копию секции. Файл без BOM, не являющийся UTF-8, читается как Latin1; значение с символами вне Latin1 туда не пишется (`ApplyBytes` возвращает null → «Некорректные правки»).
- Загрузка обновления без общего таймаута, но обрывается, если 30 с не приходит данных; кнопки «Обновить» и «Добавить в Steam» блокируют друг друга (обновление перезапускает приложение и оставило бы Steam закрытым).
- Плоские JSON-конфиги «один ключ на строку» (Remedy `renderer.ini`) правятся построчно; ключи, которых нет в файле, не добавляются, другой JSON и XML отклоняются.
- Уточнение совета в чате (`Advisor.AdjustAsync`, страница игры): контекст (совет, цель, конфиг) идёт первым блоком первого `user`-сообщения, история — парами user/assistant, последние 20 ходов; вложения только в своём ходе (в истории пометка `[вложения: …]`); пустой `settings` в ответе сохраняет прошлые пункты; модель и effort как у подбора. В API уходят текст, картинки (сжимаются до 1568 px; лимит ≈3,75 МБ сырых байт = 5 МБ base64), PDF и текстовые файлы; маска секретов в текстовых файлах — по возможности (значения строк вида ключ=значение с секретными ключами), не гарантия; в контексте совета ключи-секреты отбрасываются. Отправка идёт через тот же `asking` в `MainWindow`, что и подбор (одновременно только один запрос на окно), уход со страницы во время отправки спрашивает подтверждение. Голосовой ввод — эмуляция Win+H через `keybd_event`.
