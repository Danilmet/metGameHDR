# metGameHDR

Трей-приложение (.NET 8 / WPF). Раз в 2 с смотрит процессы и включает системный HDR, пока запущена игра из библиотеки (Steam/Epic/GOG/Ubisoft/EA/Xbox/папки); выключает через 3 с после выхода, только если включило само. Также добавляет игры из папок и выбранные приложения в Steam как non-Steam ярлыки с обложками SteamGridDB.

## Структура
- `src/metGameHDR` (root namespace `MetGameHDR`): `Scan/` источники и `Library`, `Watch/` `ProcessWatcher`, `HdrController`, `DisplayConfigHdr`, `Update/` `Updater` (самообновление с GitHub Releases), `Steam/` текстовый и бинарный VDF, `ShortcutsFile`, `SteamGridDb`, `Artwork`, `SteamAdder`, `Advice/` советчик по графике (`Hardware`, `ConfigFinder`, `ClaudeClient`, `IniEditor`, `Advisor`), `Ui/` окно (страница игры `GamePage`: цель, таблица «Сейчас | Рекомендуется», «Применить»/«Отменить»; панель деталей показывает только «подобраны/не подобраны» и «Открыть»), трей, автозапуск, `Covers` (поиск обложек + кэш загрузок SteamGridDB), `Theme` (системная тема), `Backdrop` (DWM-акрил), `Themes/Dark.xaml`, `Light.xaml`, `Controls.xaml` (стили контролов, все цвета через DynamicResource).
- `tests/metGameHDR.Tests` (xUnit), `tools/make-icon.ps1` (генерирует `src/metGameHDR/assets/icon.ico`; запускать с `-ExecutionPolicy Bypass`), спека и план в `docs/superpowers/`, отложенные темы в `docs/backlog.md`.
- Сторонних NuGet-пакетов кроме xUnit нет; комментарии в коде только там, где поведение неочевидно.

## Команды
- `dotnet build`, `dotnet test`
- `dotnet publish src/metGameHDR -c Release -o publish` — один exe, framework-dependent win-x64.
- Релиз: `git tag vX.Y.Z && git push origin vX.Y.Z` — `.github/workflows/release.yml` публикует два zip (framework-dependent и `-selfcontained`, версия из тега) и создаёт GitHub Release. CI (`ci.yml`) гоняет build и test на push/PR в master.
- `metGameHDR.exe --hdr status|on|off` — ручная проверка HDR; `--tray` — запуск без окна (так прописывается автозапуск в HKCU Run).

## Данные
`%AppData%\metGameHDR\`: `settings.json` (в том числе ключ API Claude, `ClaudeBaseUrl` — адрес сервера Claude, пусто = официальный API, `ClaudeModel` — модель, пусто = claude-opus-5-5, FPS и приоритет по умолчанию), `library.json` (на игру в `Overrides`: `HdrEnabled`, `MainExe`, `SearchName`, `Goal`, `ConfigPath` — абсолютный путь файла настроек, названный моделью (null = ещё не найден), и последний `Advice` совета по графике), `log.txt` (после 1 МБ ротация в `log.old`). Битый JSON переименовывается в `.bad`, применяются значения по умолчанию.
- `update\` — zip и распакованный релиз во время обновления; удаляется при следующем старте.
- `covers\` — обложки SteamGridDB для игр не из Steam; имя файла — безопасное имя папки игры плюс 8 hex-символов хэша пути; временные файлы пишутся как `~имя`, поэтому недокачанный файл никогда не подхватывается.

## Неочевидное
- HDR переключается через DisplayConfig `GET_ADVANCED_COLOR_INFO_2` (type 15) / `SET_HDR_STATE` (type 16), на старых Windows откат на type 9/10: на 24H2+ старый API путает HDR с автоуправлением цветом.
- При записи в Steam обложки и иконки сначала качаются при работающем Steam (appid берётся из черновой копии `shortcuts.vdf`, которая не сохраняется); затем приложение само закрывает Steam (`steam.exe -shutdown`), перечитывает файл, пишет его атомарно с копией `.bak` и запускает Steam обратно. Одна запись на игру по папке игры; appid существующих записей сохраняется; `icon` и `LaunchOptions` существующей записи перезаписываются только непустым значением.
- Один экземпляр: мьютекс `Local\metGameHDR`; повторный запуск сигналит событием `Local\metGameHDR.Show`, первый экземпляр показывает окно, второй сразу выходит. `--hdr` идёт мимо мьютекса.
- Библиотека пересканируется при каждом старте в фоне (окно сразу показывает кэш), а также после изменения папок.
- В `Settings.Apps` хранится путь, выбранный пользователем, в том числе сам `.lnk`; ярлык разрешается при сканировании, его аргументы уходят в `LaunchOptions` записи Steam. Папки без exe в корне тоже считаются играми (`MainExe = null`).
- Пути папок игр нормализуются без завершающего `\` при сканировании — это общий ключ для дедупликации, настроек игр и поиска по процессу.
- Песочница Bash/PowerShell у Claude Code на этой машине подменяет `%AppData%` и блокирует смену настроек дисплея: реальные проверки HDR/Steam/автозапуска запускать через терминал пользователя (run_in_terminal), не из песочницы.
- Обложки Steam-игр берутся из собственного кэша клиента `appcache\librarycache\<appid>\library_600x900.jpg` (старая плоская раскладка тоже проверяется) — они есть только у игр, которые Steam успел закэшировать; для этого в `Game.SteamAppId` хранится appid из манифеста. Игры из папок/приложений, уже добавленные в Steam, берут `userdata\<user>\config\grid\<appid>p.*`. Загрузка из SteamGridDB — только при заданном ключе, не более 3 параллельно; до перезапуска запоминается только «нет совпадения», сетевые ошибки повторяются при следующем пересканировании.
- Тема читается из `HKCU\...\Themes\Personalize\AppsUseLightTheme` и меняется на лету через `SystemEvents.UserPreferenceChanged`; чтобы стили перекрашивались, они обязаны использовать `DynamicResource`.
- Стекло: `DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE=38, DWMSBT_TRANSIENTWINDOW=3)` + `DWMWA_USE_IMMERSIVE_DARK_MODE=20`; при ошибке (Windows 10) окно откатывается на сплошной фон темы.
- Неявный стиль `Window` не применяется к `MainWindow` (наследник), поэтому окно явно ставит `Style="{StaticResource {x:Type Window}}"`; неявный стиль `TextBlock` принудительно задаёт цвет текста внутри шаблонов, поэтому цвета бейджей/карточек задаются через Style. Бейджи карточек показывают только проблемные состояния (`nonHDR`, зачёркнутый `Steam`).
- Обновление: при старте проверяется `releases/latest` на GitHub (через 10 с, затем раз в 24 ч); по кнопке zip качается в `%AppData%\metGameHDR\update\`, текущий exe переименовывается в `.old` (Windows это разрешает для запущенного файла), новый ставится на его место, мьютекс освобождается до `Process.Start`, иначе новый экземпляр выйдет как второй; `.old` и `update\` удаляются при следующем старте и повторно через 10 с: завершающийся старый процесс может ещё держать `.old`; если новый exe не запустился, `.old` возвращается на место и запускается старая версия. Self-contained определяется по пустому `typeof(object).Assembly.Location`.
- Советчик по графике (`Advice/`) делает два запроса: `Advisor.LocateAsync` («Найти конфиг») — модель по списку файлов папки игры и найденным кандидатам называет один файл настроек и формат (`ini`/`json`/`none`), приложение раскрывает `%LocalAppData%`/`%AppData%`/`%UserProfile%`/`%ProgramData%`/`<InstallDir>` и сохраняет путь в `ConfigPath` даже для ещё не созданного файла; затем `AskAsync` («Подобрать») — модель получает этот единственный файл (до 32 КБ, секреты замаскированы) и сама разбирает текущие значения (`Current`), а для пунктов, лежащих в файле, возвращает `Section`/`Key`/`Value` для записи. Приложение только проверяет и пишет. Путь от модели допустим лишь внутри `%LocalAppData%`, `%AppData%`, профиля, `%ProgramData%`, Documents, Saved Games или папки игры (`Advisor.IsAllowedPath`, проверяется и при чтении сохранённого пути), иначе считается «none». `AskAsync` без найденного пути уходит без файла. Цель и ответ с временем сохраняются в `library.json` на игру. Запросы не используют structured output (цитаты веб-поиска с ним дают 400): схема лежит в системном промпте, а JSON ответа собирается из text-блоков после последнего блока результата поиска (допускается ```-ограждение). Имя и exe для поиска конфигов и запроса берутся из переопределений игры. Игра должна быть закрыта для записи.
- Содержимое найденного конфига уходит в Anthropic API: только один файл, выбранный моделью на шаге поиска, до 32 К символов, значения строк, ключ которых содержит `password`, `passwd`, `pwd`, `token`, `secret`, `session`, `auth`, `ticket` или `credential`, заменяются на `***` (`ConfigFinder.MaskSecrets`). `ConfigFinder.Find` теперь только подсказывает модели пути-кандидаты в запросе поиска (порядок: Unreal по папке проекта в каталоге игры `<P>\Binaries` + `<P>\Content` → `%LocalAppData%\<P>\Saved\Config\*\GameUserSettings.ini`, Unreal по имени, `%LocalAppData%` и вложенные папки по нестрогому совпадению имени без Microsoft, Temp и т.п., корень игры, My Games и Saved Games; `steam_emu*` и `cream_api*` пропускаются). Веб-поиск у модели: до 2 обращений на поиск конфига, до 3 на подбор настроек.
- UI подбора сначала ищет конфиг (если он ещё не найден: `ConfigPath`/`ConfigNote` пусты), и только потом спрашивает совет; если файл найденного пути ещё не создан, второй запрос не отправляется. Уход со страницы игры во время запроса отменяет его после подтверждения.
- Запись конфига: при первом применении рядом создаётся `<файл>.orig` (больше не перезаписывается), при каждом применении — `<файл>.bak` с предыдущим содержимым; новое содержимое пишется через `.tmp` и `File.Move`.
- Тесты `tests/.../Advice` используют namespace `MetGameHDR.Tests`, а не `MetGameHDR.Tests.Advice`: иначе `Advice.*` внутри тестов резолвится в тестовый namespace.
- Приоритет по умолчанию и пустое поле FPS: у игры поле FPS пусто, пока нет собственной цели (показывается подсказка с FPS по умолчанию); любой ввод числа или смена приоритета создаёт цель игры, очистка поля FPS удаляет её целиком вместе с приоритетом.
- В запросе к Claude всегда явно `output_config.effort = "medium"`, чтобы стоимость не менялась при смене модели (`ClaudeModel`); `web_search` ограничен 2 использованиями при поиске конфига и 3 при подборе.
- Плоские JSON-конфиги «один ключ на строку» (Remedy `renderer.ini`) правятся построчно; ключи, которых нет в файле, не добавляются, другой JSON и XML отклоняются.
