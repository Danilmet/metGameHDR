# Одна цель вместо FPS и приоритета

Пункт бэклога «Одна цель вместо двух».

## Зачем

Сейчас у игры задаются FPS и приоритет (картинка / баланс / отзывчивость), хотя это одна ось. Отсюда противоречивые сочетания вроде «240 FPS + Картинка», и модель получает два поля, которые может трактовать по-разному. Нужна одна цель, выбираемая одним действием. Модель по-прежнему сама подбирает настройки.

Успех: у игры ровно одна цель, модель получает её однозначно, данные из старых версий загружаются без ошибок.

## Решения

- Цель — ползунок из 5 шагов «Качество ←→ Производительность».
- FPS шага считает приложение от частоты монитора и показывает под ползунком; модель получает шаг и число.
- Старые цели (`Goal` в `library.json`, `DefaultFps`/`DefaultPriority` в `settings.json`) не переносятся: сбрасываются на значение по умолчанию.
- Не делаем: своё число FPS на шаге, цели по профилям или сценам, перенос старых целей.

## Данные

`Advice/Models.cs`: `Priority` и `GraphicsGoal` удаляются, вместо них

```csharp
[JsonConverter(typeof(JsonStringEnumConverter))]
public enum GoalStep { MaxQuality, Pretty, Balanced, Smooth, MaxFps }
```

и чистая функция `GoalTargets.For(GoalStep step, int hz)` → `(int? Fps, GoalKind Kind)`, где `GoalKind` — `AtLeast` (не ниже), `Target` (цель), `Unlimited` (без потолка, `Fps = null`). Частота `hz <= 0` считается как 60.

| Шаг | Подпись | FPS | Kind |
|---|---|---|---|
| MaxQuality | Макс. качество | 30 | AtLeast |
| Pretty | Красиво | min(60, hz) | Target |
| Balanced | Баланс | середина Pretty и Smooth, округление до 10 | Target |
| Smooth | Плавно | hz | Target |
| MaxFps | Макс. FPS | null | Unlimited |

Примеры: 60 Гц → 30/60/60/60/—; 144 → 30/60/100/144/—; 165 → 30/60/110/165/—; 240 → 30/60/150/240/—. Середина: `(int)Math.Round((pretty + smooth) / 20.0, MidpointRounding.AwayFromZero) * 10`, затем `Math.Clamp(mid, pretty, smooth)` — на нестандартных частотах округление может выйти за край (59 Гц: 60 > 59). Примеры: 112,5 → 110, 102 → 100, 105 → 110; 59 Гц → 59.

Хранение:

- `GameOverride.Goal` удаляется, добавляется `GoalStep? Target` (null — значение по умолчанию).
- `Settings.DefaultFps` и `Settings.DefaultPriority` удаляются, добавляется `GoalStep DefaultTarget = Balanced`.

Имена свойств новые нарочно: старый объект `"Goal": {"Fps":…,"Priority":…}` не должен разбираться в enum, иначе загрузчик сочтёт весь файл битым и переименует его в `.bad`. System.Text.Json пропускает незнакомые поля, поэтому старые цели исчезают при загрузке и из файла при следующем сохранении. Советы, пути конфигов и прочие переопределения не затрагиваются.

## Запрос к модели

- `AdviceRequest.Goal` → `GoalStep Goal`; `Advisor.AskAsync(Game game, GoalStep goal, CancellationToken ct)` сохраняет `Target` игры, как раньше `Goal`.
- `ClaudeClient.BuildAskBody`: вместо `goal = r.Goal` уходит `goal = { mode, fps }`, `mode` ∈ `max_quality`, `quality`, `balanced`, `smooth`, `max_fps`; `fps` — из `GoalTargets.For(goal, hardware.Hz)` (null у `max_fps`). Частота уже есть в `hardware.hz`.
- В `AskPrompt` вводное «цель (кадры в секунду и приоритет: …)» заменяется на «цель (режим и кадры в секунду)», а фраза «Цель по кадрам — для типичных сцен, с запасом ~10%» в правиле 2 — новым правилом о режимах:
  - `max_quality` — максимум картинки, кадры как получатся, но не ниже `fps`;
  - `quality` — стабильно держать `fps`, весь остальной запас отдать картинке;
  - `balanced` — держать `fps` в типичных сценах, жертвовать самым дорогим при малой разнице в картинке;
  - `smooth` — держать `fps` с запасом и по минимальным кадрам (1% low), картинка во вторую очередь;
  - `max_fps` — как можно больше кадров и минимальная задержка, картинка вторична;
  - для режимов с целью — для типичных сцен, с запасом ~10%.

## Интерфейс

- **Страница игры.** Поле FPS и список приоритета заменяются ползунком (`Slider`, 0–4, деления с привязкой, подписи «Качество» слева и «Производительность» справа). Под ним строка шага: «Баланс · цель ~110 FPS», «Макс. качество · не ниже 30 FPS», «Макс. FPS · без ограничения»; без своей цели — с хвостом « (по умолчанию)». Пока своей цели нет, ползунок стоит на значении по умолчанию. Сдвиг создаёт цель игры, рядом появляется ссылка «Сбросить» (возврат к значению по умолчанию). Во время запроса ползунок заблокирован (`IsIdle`). При открытии страницы фокус на ползунке.
- **Сохранение.** Изменение цели игры пишется через существующий `GameRow.SaveSoon` (500 мс после последнего изменения).
- **Настройки.** «FPS по умолчанию» и «Приоритет по умолчанию» заменяются тем же ползунком с той же строкой (без хвоста). Изменение сохраняет настройки и вызывает `NotifyDefaultsChanged`, чтобы обновились строки игр без своей цели.
- **`GameRow`.** Вместо `GoalFps`, `FpsHint`, `GoalPriority`: `int TargetIndex` (get/set для ползунка), `string TargetText`, `bool HasOwnTarget`, `void ResetTarget()`; `Goal` возвращает `GoalStep`. Конструктор вместо `Func<GraphicsGoal>` получает `Func<GoalStep>` для значения по умолчанию и `Func<int>` для частоты.
- **Подпись** строится одной функцией `GoalTargets.Label(GoalStep step, int hz, bool isDefault)`, общей для страницы и настроек.

## Тесты

- `GoalTargets.For`: таблица 60/144/165/240 Гц по всем шагам; `hz = 0` → как 60.
- `GoalTargets.Label`: по строке на каждый `Kind` и хвост « (по умолчанию)».
- `ClaudeClient.BuildAskBody`: в теле `goal.mode` и `goal.fps`; у `max_fps` `fps` равен null.
- `Advisor.AskAsync`: сохраняет `Target` (вместо прежней проверки `Goal`).
- `Library.Load` старого файла с объектом `Goal` у переопределения: файл не переименован в `.bad`, `Target` = null, `HdrEnabled`/`ConfigPath` на месте.
- `Settings.Load` старого файла с `DefaultFps`/`DefaultPriority`: не битый, `DefaultTarget` = `Balanced`, остальные поля на месте.
