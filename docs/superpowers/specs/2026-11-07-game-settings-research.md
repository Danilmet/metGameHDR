# ADR: настройки игр — подбор внутриигровых графических настроек

Статус: Предложено.

Связанное: спека `docs/superpowers/specs/2026-11-07-gamehdr-design.md`; техническая справка с источниками, ID настроек и ключами реестра — заметка `game-settings-research-details.md` в общей папке заметок сессий.

## Контекст

У современных игр десятки графических настроек с неочевидным влиянием на кадровую частоту и картинку. Пользователь хочет формулировать цель — например «стабильные 120 кадров на моём мониторе» или «максимум качества при 60» — и получать готовый набор настроек, а не подбирать их вручную.

Что есть у других:

- NVIDIA app держит закрытую облачную базу «оптимальных настроек», размеченную на фермах под связку процессор + видеокарта + монитор, и записывает их в конфиги игр. Покрытие больше тысячи игр, профили выходят с обновлениями приложения, то есть для новых игр с задержкой. Только для видеокарт NVIDIA, без цели по кадрам.
- AMD Adrenalin советует правки текстом, применять их нужно в меню игры. Intel аналога не имеет.
- Открытой вендорно-нейтральной базы «железо + цель → настройки» нет. Знание разбросано по статьям Digital Foundry, Hardware Unboxed, форумам и PCGamingWiki.

Приложение уже знает список установленных игр, их папки и главный exe, следит за процессами и держит настройки на игру. Доступ к Claude API у владельца есть; модель с серверным веб-поиском умеет собрать разрозненные рекомендации по конкретной игре и свести их к конфигурации железа пользователя.

Иное прочтение термина «настройки игр» — действия при запуске (смена частоты монитора, аудиоустройства, профили драйвера NVIDIA, Windows Auto HDR на exe) — владелец на уточняющий вопрос не выбрал; собранные по нему находки лежат в технической справке.

## Варианты

### Вариант 1. Советчик: рекомендации текстом

```
пользователь: цель на игру ──► приложение: цель + игра + железо + монитор
                                        │
                                        ▼
                               Claude API (+ веб-поиск)
                                        │
                                        ▼
                      список настроек со значениями и пояснениями
                                        │
                                        ▼
                    карточка игры в окне; пользователь выставляет сам
```

Приложение определяет железо (видеокарта и память, процессор, ОЗУ, разрешение и частота монитора), отправляет его вместе с названием игры и целью, получает структурированный ответ, показывает его и кэширует на игру. Применение — руками в игре.

Плюсы: работает для любой игры и любого вендора, включая игры, вышедшие вчера; не трогает файлы игр, ничего не ломает; нет зависимости от формата конфигов; покрывает заявленную боль целиком.

Минусы: модель может ошибиться в названиях настроек или диапазонах, особенно для редких игр; нет обратной связи по фактическому результату; расход на запрос порядка нескольких центов; нужен ключ API и сеть.

Объём работы: небольшой — определение железа, один HTTP-запрос с разбором ответа, поле цели и панель рекомендаций в карточке игры, ключ API в настройках.

### Вариант 2. Применятель: запись в конфиг игры

```
вариант 1 ──► модель дополнительно называет файл конфига и ключи
                      │
                      ▼
      приложение: игра закрыта? → резервная копия → разбор файла
                      │
                      ▼
             показ диффа → подтверждение → запись
```

Для игр с текстовым конфигом (прежде всего Unreal Engine, где уровни качества лежат в одном INI-файле с единообразными ключами) приложение само применяет рекомендации. Остальные игры получают только текст, как в варианте 1.

Плюсы: «нажал и готово» для самой распространённой категории игр; остаётся совместимым с вариантом 1 как запасным путём.

Минусы: форматы конфигов разнородны (реестр и бинарные блобы в Unity, бинарные профили Frostbite); игра может перезаписать конфиг при выходе или сбросить его при невалидных значениях; облачные сохранения Steam/Epic могут вернуть старую копию; требуется закрытая игра; ошибка в пути или ключе портит настройки пользователя.

Объём работы: средний — поверх варианта 1 парсер и писатель INI с сохранением неизвестных строк, поиск конфига по эвристике и ответу модели, резервные копии, экран диффа.

### Вариант 3. Замкнутый цикл с измерением кадров

```
вариант 2 ──► запуск игры ──► измерение времени кадра
                                      │
                                      ▼
                    отклонение от цели → новый запрос к модели → правка
```

Приложение измеряет реальную кадровую частоту во время игры и итеративно подгоняет настройки под цель.

Плюсы: единственный вариант, который проверяет результат, а не предполагает его.

Минусы: трассировка кадров через ETW требует членства в группе «Пользователи журналов производительности» или прав администратора, что противоречит правилу приложения работать без повышения прав; альтернативы завязаны на сторонний RivaTuner; кадровая частота зависит от сцены, одно измерение малоинформативно; каждая итерация — перезапуск игры и новый платный запрос.

Объём работы: большой — всё из варианта 2 плюс сбор телеметрии кадров, логика итераций, обработка разовой настройки прав.

### Вариант 4. Не делать

Оставить подбор настроек NVIDIA app, AMD Game Advisor и статьям; приложение остаётся инструментом HDR и ярлыков Steam.

Плюсы: ноль кода, ноль новых зависимостей и рисков.

Минусы: боль остаётся; вендорные инструменты запаздывают для новых игр и не работают от цели по кадрам.

Объём работы: нет.

## Сравнение

| | 1. Советчик | 2. Применятель | 3. Замкнутый цикл | 4. Не делать |
|---|---|---|---|---|
| Объём работы | небольшой | средний | большой | нет |
| Покрытие игр | все | все (запись — в основном Unreal) | все (запись — Unreal) | — |
| Риск сломать игру | нет | есть, смягчается копиями и диффом | есть | нет |
| Права администратора | нет | нет | нужны разово | нет |
| Проверка результата | нет | нет | есть | — |
| Новые зависимости | ключ API, сеть | те же | те же + ETW или RivaTuner | нет |
| Стоимость для пользователя | центы на игру | центы на игру | центы на итерацию | нет |

## Решение

Рекомендуется вариант 1. Он один закрывает заявленную боль — «слишком много настроек, непонятно какие выставить под мою цель» — при минимуме кода и без риска для файлов игр, и при этом является первым этапом вариантов 2 и 3: если практика покажет, что ручное выставление утомляет, запись конфигов Unreal добавляется поверх без переделки.

Варианты 2 и 3 откладываются до опыта с вариантом 1. Вариант 3 дополнительно противоречит принципу приложения не требовать прав администратора.

## Последствия

- В приложении появляется сетевой компонент и хранение ключа Claude API; при отсутствии ключа или сети функция скрыта, остальное приложение от неё не зависит.
- Настройки на игру расширяются целью и кэшем последней рекомендации; формат хранения библиотеки меняется совместимо.
- Появляется определение железа — отдельный модуль без прав администратора.
- Пункт спеки «конфигурируемость сверх описанной не делаем» уточняется: добавляется одна настройка на игру (цель) и одна глобальная (ключ API). Запреты на RTX HDR и Auto HDR на exe остаются в силе.
- Каждый запрос стоит денег владельца; нужен кэш на игру и явная кнопка «обновить рекомендации», а не автоматические запросы.

## Открытые вопросы

- Форма цели: число кадров, выбор из «производительность / баланс / качество», или и то и другое; разумное значение по умолчанию — частота монитора.
- Какая модель и глубина рассуждения: более дорогая даёт качественнее синтез статей, более дешёвая — центы за запрос; нужен один замер на нескольких играх.
- Нужна ли простая обратная связь без телеметрии: кнопки «стало лучше / хуже» как вход в следующий запрос.
- Что показывать для игр, по которым модель ничего не нашла: честное «данных нет» или общие советы по движку.
- Стоит ли сразу закладывать запись конфигов Unreal как следующий шаг или ждать запроса от практики.
