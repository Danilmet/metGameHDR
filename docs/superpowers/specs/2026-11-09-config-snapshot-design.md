# Текущие настройки сразу после поиска конфига

Пункты бэклога «Текущие настройки сразу после поиска конфига» и «Таблица качества Unreal».

## Зачем

После «Найти конфиг» страница игры показывает только путь к файлу; что сейчас выставлено в игре, видно лишь после «Подобрать». Нужно: сразу после поиска таблица показывает текущие настройки подписями меню игры (сырые ключи не показываем), а подбор переиспользует этот разбор и не становится дороже.

Успех: после поиска таблица «Настройка | Сейчас» заполнена; для Unreal-игр строки `sg.*` видны мгновенно, без модели; подбор не отправляет лишних запросов.

## Решения

- Третий запрос к модели — «разобрать конфиг» — сразу после поиска (если файл существует) и по ссылке «Конфиг изменился — Обновить».
- Изменение файла определяется по времени записи; само по открытию страницы ничего не запрашивается.
- Локальная таблица Unreal `sg.*` делается в этой же задаче.
- Не делаем: фоновое слежение за файлом, разбор при открытии страницы, разбор без найденного пути, разбор формата `none`.

## Данные

`Advice/Models.cs`:

```csharp
public sealed record CurrentSetting(string Name, string? Current, string? Section, string? Key);
public sealed record ConfigSnapshot(List<CurrentSetting> Settings, DateTime At, DateTime FileStamp);
```

`GameOverride.Snapshot` (`ConfigSnapshot?`, null — разбора нет). `FileStamp` — `File.GetLastWriteTimeUtc(path)` на момент разбора.

Разбор **устарел**, если файл найденного пути существует и его `GetLastWriteTimeUtc` ≠ `FileStamp`, или если найденный путь сменился («Найти заново» нашёл другой файл — тогда снимок сбрасывается в null). `Advisor.IsSnapshotFresh(Game game) : bool`.

## Запрос «Разобрать»

- `Advisor.ReadAsync(Game game, CancellationToken ct) : Task<ConfigSnapshot?>` — берёт найденный путь (`LocatedPath`), читает файл тем же `ReadConfig` (до 32 К символов, `MaskSecrets`), отправляет `ClaudeClient.ReadAsync(ReadRequest, ct)`, применяет локальную таблицу Unreal (см. ниже), сохраняет `Snapshot` с `FileStamp` и пишет `library.json`. Без найденного или существующего файла возвращает null, запрос не отправляет.
- `ReadRequest(Game Game, string ConfigPath, string ConfigFormat, string ConfigText, bool Truncated)`.
- Тело: `max_tokens` 4000, `output_config.effort = "low"`, **без** `tools`; user: `game`, `config {path, format, text, truncated}`.
- Промпт `ReadPrompt`:

```text
Ты знаешь графические настройки ПК-игр. Тебе дают игру и её файл настроек с содержимым.
Правила:
1. settings — пункты графического меню игры, которые хранятся в этом файле, в порядке, в каком они обычно идут в меню. name — подпись пункта так, как она видна в меню игры (на языке игры, если неизвестен — по-английски).
2. current — текущее значение, переведённое в подпись меню (например ключ 3 → "High"); если значение не удаётся понять — сырое значение из файла.
3. section — секция INI или null, key — точное имя ключа из файла. Ключи не выдумывай; пункты, которых нет в файле, не включай.
4. Служебные ключи (версии, идентификаторы, пути, статистику) не включай.
Отвечай только одним JSON-объектом по схеме, без пояснений и без markdown-ограждений:
{"type":"object","additionalProperties":false,"required":["settings"],"properties":{"settings":{"type":"array","items":{"type":"object","additionalProperties":false,"required":["name","current","section","key"],"properties":{"name":{"type":"string"},"current":{"type":["string","null"]},"section":{"type":["string","null"]},"key":{"type":["string","null"]}}}}}}
```

Ответ разбирается тем же механизмом, что и у подбора (JSON из text-блоков, допускается ```-ограждение).

## Таблица Unreal

`Advice/UnrealScalability.cs`, `static class UnrealScalability`:

- `static CurrentSetting? Describe(string? section, string key, string rawValue)` — для секции `ScalabilityGroups` (без учёта регистра) и известных ключей возвращает строку, иначе null.
- Уровни 0–4 → `Low`, `Medium`, `High`, `Epic`, `Cinematic`; другое целое — сырое значение.
- Ключи и подписи:

| Ключ | Подпись |
|---|---|
| sg.ResolutionQuality | Масштаб разрешения (значение `"{N}%"`, N — число, округлённое до целого) |
| sg.ViewDistanceQuality | Дальность прорисовки |
| sg.AntiAliasingQuality | Сглаживание |
| sg.ShadowQuality | Тени |
| sg.GlobalIlluminationQuality | Глобальное освещение |
| sg.ReflectionQuality | Отражения |
| sg.PostProcessQuality | Постобработка |
| sg.TextureQuality | Текстуры |
| sg.EffectsQuality | Эффекты |
| sg.FoliageQuality | Растительность |
| sg.ShadingQuality | Затенение |

- `static List<CurrentSetting> FromFile(string text)` — строки для всех известных ключей файла (значения через `IniEditor.CurrentValue`), в порядке таблицы.
- Применение: сразу после поиска (до ответа разбора) страница показывает `FromFile` как временную таблицу. В ответе разбора у строк, для которых `Describe` вернул строку, `Current` заменяется локальным значением (имя от модели остаётся). Если модель пропустила известный ключ — строка из `FromFile` добавляется в конец.

## Подбор

- `AdviceRequest` получает `List<CurrentSetting>? Current`; `BuildAskBody` кладёт `current` в user, только если снимок свежий (иначе null).
- В `AskPrompt` к правилу о `current` добавляется: «Если прислан current — это уже разобранные пункты файла: бери из него name и current для этих пунктов».
- После ответа `AskAsync` обновляет `Snapshot` из строк ответа с `Key != null` (`Name`, `Current`, `Section`, `Key`; Unreal-подписи через `Describe`), `At` = сейчас, `FileStamp` = текущее время записи файла — если файл существует. Отдельный запрос разбора при этом не отправляется.

## Запись и восстановление

`Advisor.Apply` и `Advisor.Restore` после записи файла обновляют снимок без запроса: для `Apply` — `Current` строк с совпавшими `(Section, Key)` берётся из `Recommended` совета; для `Restore` — из `IniEditor.CurrentValue` восстановленного файла (через `Describe` для Unreal, иначе сырое); `FileStamp` — новое время записи. Существующее обновление `Current` в совете остаётся.

## Интерфейс

- **«Найти конфиг» / «Найти заново»:** поиск → если файл существует и формат не `none`, сразу разбор; этап «Разбираем конфиг…». До ответа таблица показывает `UnrealScalability.FromFile`, если что-то нашлось.
- **«Подобрать»:** если не найден — поиск, разбор, подбор; если найден — сразу подбор (без отдельного разбора).
- **Таблица.** Без совета: строки снимка (или временные Unreal-строки), «Рекомендуется» — «—», «Применить» недоступна; подсказка «Нажмите «Подобрать»…» остаётся под таблицей. С советом: строки совета; «Сейчас» для строк с ключом — из снимка по совпадению `(Section, Key)` без учёта регистра, если снимок свежий, иначе из совета.
- **«Конфиг изменился — Обновить»:** ссылка рядом со строкой конфига, видна при устаревшем снимке существующего файла; запускает только разбор; недоступна во время запроса (`IsIdle`).
- **Ошибки:** неудачный разбор — статус «Не удалось разобрать конфиг: <сообщение>», снимок и таблица не меняются, страница работает дальше.
- `GameRow`: `HasSnapshot`, `SnapshotStale`, построение строк таблицы с учётом снимка (`BuildRows`), обновление при `RefreshConfig`/`LoadAdvice`.

## Тесты

- `ClaudeClient.BuildReadBody`: нет `tools`, `effort` = `low`, `config.text` приложен; разбор ответа в список `CurrentSetting`.
- `Advisor.ReadAsync`: сохраняет `Snapshot` с `FileStamp`; без файла — null и без запроса; секреты замаскированы в отправленном тексте.
- Устаревание: смена времени записи файла → `IsSnapshotFresh` false; «Найти заново» с другим путём сбрасывает снимок.
- `Apply` и `Restore` обновляют снимок и `FileStamp` (снимок остаётся свежим).
- `BuildAskBody`: `current` есть при свежем снимке, null при устаревшем; `AskAsync` обновляет снимок из ответа.
- `UnrealScalability`: уровни 0–4, неизвестное число → сырое, `ResolutionQuality` "100.000000" → "100%", чужая секция или ключ → null; `FromFile` порядок по таблице; подмена `Current` в ответе разбора и дозаполнение пропущенного ключа.
- `GameRow`-логика сборки строк вынесена в чистую функцию `AdviceTable.Build(Advice?, ConfigSnapshot?, bool fresh)` → строки таблицы; тест: «Сейчас» из снимка по ключу, без снимка — из совета, без совета — строки снимка с «—».
