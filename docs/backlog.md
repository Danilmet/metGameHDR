# Бэклог

Отложенные темы, не вошедшие в текущие ветки. Каждая — кандидат на отдельную ветку.

## Советчик по графике

- **Конфиги в реестре (Unity PlayerPrefs).** `HKCU\Software\<Компания>\<Игра>`, имена значений с хвостом `_h<хэш>`, int как DWORD, float как DWORD с битами float, строки как REG_BINARY UTF-8 с нулём. Поиск: модель отвечает форматом `registry` и путём ключа, приложение проверяет, что ключ под `HKCU\Software`. Отправка: выгрузка ключа строками `имя=значение`. Запись: по точному имени с сохранением типа, копия ветки в `.reg` вместо `.orig/.bak`, игра должна быть закрыта (Unity перезаписывает PlayerPrefs при выходе). Польза выше у тяжёлых Unity-игр; у многих там только разрешение и VSync.
- **Таблица качества Unreal.** Зашить соответствие `sg.*` → «Low / Medium / High / Epic / Cinematic», чтобы «Сейчас» показывалось словами даже без модели и проверялось локально.
- **Порядок поиска кандидатов.** `My Games` раньше корня игры, ключевое слово `prefs` (Bethesda `*Prefs.ini`), чтобы мусорные `.ini` в корне не занимали лимит.
- **Одна цель вместо двух.** Сейчас задаются и FPS, и приоритет (картинка / баланс / отзывчивость), хотя это одна ось: пользователь выбирает либо целевой FPS (модель сама решает, чем жертвовать), либо режим качества (модель сама решает, сколько кадров реально). Варианты: переключатель «по FPS / по качеству» с одним полем, или ползунок как у NVIDIA с подписью, во что он выливается.
- **Текущие настройки сразу после поиска конфига.** Когда конфиг найден, страница должна показывать фактические значения ещё до подбора. Дёшево: таблица «ключ — значение» прямо из файла (INI/JSON уже разбираем), без модели. Красиво: отдельный короткий запрос «разбери конфиг в подписи меню» (имя пункта, текущее значение словами), результат кэшируется и переиспользуется шагом подбора, чтобы не платить дважды. Для Unreal подписи `sg.*` можно давать без модели (см. таблицу качества). Решение: делать вариант с моделью, сырые ключи не показывать.
- **Сброс к копии.** Кнопка «Вернуть исходный конфиг» из `.orig`.
- **Обратная связь без телеметрии.** Кнопки «стало лучше / хуже» как вход в повторный запрос.
- **Корректировка подбора вместе с моделью.** После совета пользователь уточняет словами («тени повыше», «просадки в городе», «верни сглаживание») и модель правит рекомендации с учётом прошлого ответа, текущего конфига и цели, а не подбирает с нуля.

## Новые фичи

- **Оверлей с чатом в игре.** Поверх игры окно чата с подсказками по игре, ввод голосом и текстом. Модели автоматически уходит контекст: игра, текущие настройки, железо, последний совет, по возможности скриншот. Отдельная большая тема: хоткей, оверлей поверх полноэкранных игр, распознавание речи, стоимость запросов.
- **How Long to Beat.** Время прохождения (сюжет / сюжет + доп. / 100%) на странице игры и, возможно, на карточке; данные с howlongtobeat.com, кэш в `library.json`. Официального API нет — нужен устойчивый к изменениям сайта способ получения.
- **Скрывать игры.** Галочка «скрыть» на карточке, скрытые не показываются в сетке и не следятся по HDR; фильтр «показать скрытые».

## Интерфейс

- **Детали на обороте карточки.** Вместо боковой панели, из-за которой сдвигается вся сетка, карточка переворачивается и показывает детали на обратной стороне.
- **Список игр слева на странице настроек.** Когда открыт экран подбора, остальные игры сжимаются в вертикальную колонку иконок слева, чтобы переключаться между играми не выходя назад.
- **Высокая кнопка «Назад»** на странице игры — по высоте обложки, как визуальная пара к ней.
- **Выпадающие списки в настройках** вместо текстовых полей там, где набор значений известен (модель, приоритет по умолчанию).

## Настройки

- **Модель и effort под каждую задачу.** Отдельно для поиска конфига и для подбора (а в будущем для разбора конфига и чата): дешёвая модель с низким effort для поиска, сильная для подбора. Сейчас одна модель на всё и effort зашит как medium.
